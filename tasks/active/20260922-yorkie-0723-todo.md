# Upgrade Yorkie 0.7.13 → 0.7.23

**Created**: 2026-09-22
**Issue**: none — prompted by a measurement in `20260922-version-history-lessons.md` turning out to
be version-specific.
**Design**: no new design doc. This changes no behaviour the app defines; it moves a pin and
re-checks every measured assumption that pin is holding up. Those assumptions live in
`docs/adr/007-block-array-not-tree.md` and `docs/design/version-history.md`.

## Why now

The version-history task (#117) rejected `client.restoreRevision()` on two measured defects. One of
them — a `)` inside any string silently becoming `}` — was **fixed upstream in v0.7.19** by
[yorkie#1967](https://github.com/yorkie-team/yorkie/pull/1967), which we found only after the branch
was written. This upgrade lands first so #117 can be rebased onto it and shed whatever the new
version makes unnecessary, rather than merging code and deleting it a day later.

## Milestones

### 1. Move the pin

- **What**: `@yorkie-js/sdk` and the server image both go 0.7.13 → 0.7.23.
- **Files**: `package.json`, `pnpm-lock.yaml`, `docker-compose.yml:47`, `patches/`.
- **Reuse**: the existing `exports`-map patch, re-created under the new version's name — 0.7.23
  still ships neither `module` nor `exports`, so the dual-package hazard that
  `tasks/archive/2026/07/20260728-yorkie-git-spike-lessons.md` documents is unchanged.
- **Done**: `pnpm lint && pnpm test && pnpm build` pass with no test changed.

### 2. Re-check what the old pin was holding up

- **What**: re-run the measurements the docs cite as load-bearing, since nothing in CI covers them.
- **Files**: throwaway probes (not committed); results into the lessons file and the docs that
  make the claims.
- **Reuse**: the probe shapes already written down in `20260922-version-history-lessons.md` and
  ADR-007's evidence section — re-running a recorded measurement is cheaper than inventing one.
- **Done**: six results recorded, and every doc sentence that names the pin either updated or
  marked as measured-on-the-old-one.

### 3. Verify against the container, not `pnpm dev`

- **What**: existing `.data/` and Mongo volumes still read, and the app still works end to end.
- **Done**: `pnpm docker:up` on the new image, `welcome` opens with its history intact, two
  browsers edit concurrently.
