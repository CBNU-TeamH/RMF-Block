# Upgrade Yorkie and the JS SDK 0.7.23 → 0.7.28

**Created**: 2026-11-17
**Issue**: none — a version bump, planned here.
**Design**: no new design doc. No behaviour the app defines changes; this moves both pins, shrinks the SDK patch to the
half upstream has not fixed, and re-checks what the old pins were holding up. The claims it touches live in
`docs/adr/003-stack-choices.md`, `docs/design/version-history.md` and `scripts/verify-yorkie-invariants.mjs`.

## Why now

- **The `exports` half of our patch is upstream.** SDK 0.7.26 ships its own `exports` map (yorkie-js-sdk#1431), and
  0.7.27 restores the full default export that 0.7.26 broke (#1520). ADR-003's "the patch comes out once upstream
  declares `exports`" can finally be acted on, for that half.
- **Reconnect and presence fixes.** A Watch stream that goes silent past the server heartbeat now reconnects (#1472,
  #1483); a peer's presence survives its stream unwatching (#1501); presence goes as a patch to a server that supports
  it (#1477), which matters for `ink-overlay.tsx`'s pointer/marks traffic.
- **Text undo convergence and GC fixes** across 0.7.24–0.7.26, which `doc.history` on text and table blocks uses.
- **Server 0.7.24 fixes the likely root cause of #257** (yorkie#2112: a client's row could be cached out of order when
  two of its PushPulls finished in reverse, leaving a stale per-document checkpoint). Inferred from source, not measured.

## Milestones

- **What**: `@yorkie-js/sdk` 0.7.23 → 0.7.28 and `yorkieteam/yorkie:0.7.23` → `0.7.28`. The patch is regenerated with
  `pnpm patch @yorkie-js/sdk@0.7.28` / `pnpm patch-commit`: the `package.json` `exports` hunk goes, and the serial-await
  change is re-applied to `Client.sync()` and `runSyncLoop` in both `dist/yorkie-js-sdk.es.mjs` and `dist/yorkie-js-sdk.js`,
  keeping 0.7.28's new `trackSync` / `captureSession` / write-rejected handling intact.

## Cross-cutting

- No FR change, no schema change, no app code expected to change.
- **One-way door**: once a 0.7.26+ client has written to a volume, rolling the server back below 0.7.26 is unsupported
  (Text removal ledger, presence patch). Release notes for hosts say so, and say that a `.env` secret under 32 characters
  now stops Yorkie from starting.
- Out of scope, noted for later: `AdminService.RevalidateAccess` (server 0.7.24) could cut a kicked guest's open Watch
  stream on kick (UC-011); the webhook method `WatchDocument` is deprecated in favour of `Watch`; `fetchToken` returning
  `""` bypasses the SDK's new token-refresh backoff (#1513). None is needed for this bump.
- The perf campaign measured on 0.7.23 (`docs/perf/runbook-ko.md` pins the app image too); numbers from before this bump
  are not comparable to after without a re-run. `e2e/perf/stack.ts` takes Yorkie from `docker-compose.yml`, so after
  this bump a perf round runs the pinned v0.3.0 app (SDK 0.7.23) against server 0.7.28 — an older client on a newer
  server, which upstream supports, but a third configuration the campaign has not measured.
